# FlavorFit — сервер

GraphQL-сервер: авторизация, профили, рецепты с пищевой ценностью, заказы ингредиентов.

Code-first — схема собирается из классов и декораторов, отдельного `.graphql`-файла нет. За это платишь тем, что схему невозможно прочитать целиком в одном месте, зато она физически не может разъехаться с кодом.

Клиент: **[FlavorFit](https://github.com/muhammad2008nur/FlavorFit)**

## Что работает

- [x] Регистрация и вход, пароли через argon2
- [x] JWT в куках: access на час, refresh на три дня, обе `httpOnly`
- [x] Новая пара токенов по refresh-куке
- [x] Подтверждение почты, токен живёт час
- [x] Сброс пароля, токен живёт 30 минут
- [x] Письма через Resend, шаблоны на react-email
- [x] Turnstile проверяется в гарде, до резолвера
- [x] Профиль и замеры тела
- [ ] Резолверы рецептов
- [ ] Лайки и комментарии
- [ ] Заказы

## База

14 моделей, схема разбита по файлам в `prisma/schema/`.

| Группа | Модели |
|---|---|
| Пользователь | `User`, `Profile`, `BodyMeasurements` |
| Рецепты | `Recipe`, `Ingredient`, `RecipeIngredient`, `RecipeStep`, `NutritionFact`, `RecipeTag` |
| Активность | `Comment`, `Like` |
| Заказы | `Order`, `OrderItem`, `Courier` |

`RecipeIngredient` и `NutritionFact` вынесены отдельно не для красоты. Один ингредиент участвует в десятках рецептов с разным количеством и единицами измерения — связь многие-ко-многим с полезной нагрузкой, её не свернуть в массив. КБЖУ отделены от рецепта, потому что рецепт без них валиден, а тащить четыре nullable-поля Decimal в основную таблицу не хотелось.

Имена полей проброшены через `@map`: в базе snake_case, в коде camelCase.

## Авторизация

Токены не уходят в теле ответа. Только куки, только `httpOnly` — из JavaScript их не достать ни аналитике, ни подменённой зависимости, ни XSS. В проде добавляется `secure` и `sameSite: strict`, на `localhost` послабления, иначе браузер куку не примет.

Капча вешается декоратором `@VerifyCaptcha()`. Он включает `TurnstileGuard`, тот достаёт токен из `cf-turnstile-token` и проверяет у Cloudflare **до** того, как резолвер начнёт работу — то есть до похода в базу.

Сначала всё лежало в одном `AuthService`, и он разросся до состояния, когда искать в нём что-то стало неприятно. Разнёс по трём:

| Сервис | За что отвечает |
|---|---|
| `AuthService` | вход, регистрация, проверка пароля |
| `AuthCookieService` | генерация JWT, установка и удаление кук, новая пара по refresh |
| `AuthAccountService` | подтверждение почты, запрос и выполнение сброса пароля |

## Известные проблемы

Нет лимита на частоту запросов к `login` и сбросу пароля. Turnstile отсекает ботов, но не мешает перебирать пароли с одного живого клиента — это дыра, и её надо закрыть раньше остальных планов.

Тестов нет.

## Запуск

Нужен Node 20+ и PostgreSQL.

```bash
git clone https://github.com/muhammad2008nur/FlavorFit-backend.git
cd FlavorFit-backend
npm install
cp .env.example .env
npx prisma migrate dev
npm run start:dev
```

Playground на `localhost:4000/graphql`.

| Переменная | Описание |
|---|---|
| `DATABASE_URL` | подключение к PostgreSQL |
| `JWT_SECRET` | секрет для подписи токенов |
| `CLIENT_URL` | адрес фронтенда, из него собираются ссылки в письмах |
| `RESEND_API_KEY` | ключ Resend |
| `TURNSTILE_SECRET_KEY` | приватный ключ Turnstile |
| `NODE_ENV` | `development` или `production` |
